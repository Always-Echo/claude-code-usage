技术栈选择

用什么技术来构建这个 macOS 菜单栏 app？

A

Swift + SwiftUI（推荐）

原生 macOS 开发，NSStatusItem + NSPopover + SwiftUI 视图。性能最好，体积最小，系统集成最深。

优点

  • 原生性能，内存占用极低（~10MB）
  • SwiftUI 可实现精美自定义 UI
  • 直接读取本地文件，无需 Node.js 运行时
  • 可打包为标准 .app

缺点

  • 需要 Xcode
  • Swift 语言学习成本（若不熟悉）
B

Electron + TypeScript

基于 Web 技术（HTML/CSS/JS）构建，可复用 ccusage 的 TypeScript 数据解析逻辑。

优点

  • 可直接复用 ccusage 的数据解析代码
  • Web 技术栈熟悉度高
  • UI 灵活，CSS 直接套用 Supabase 设计

缺点

  • 内存占用大（~150MB+）
  • 包体积大（~100MB+）
  • 启动慢
C

Tauri + TypeScript

Rust 后端 + WebView 前端，兼顾轻量和 Web 技术栈。可复用 ccusage 数据逻辑，包体积远小于 Electron。

优点

  • 包体积小（~5MB），内存低（~30MB）
  • 前端用 Web 技术，可复用 TS 逻辑
  • 支持 macOS 菜单栏 tray

缺点

  • Rust 后端有一定学习成本
  • macOS 菜单栏支持不如原生完善
